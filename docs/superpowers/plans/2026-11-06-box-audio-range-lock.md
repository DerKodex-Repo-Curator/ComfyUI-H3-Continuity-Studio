# Lock Audio to Boxes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the user-selected Native execution. Steps use checkbox syntax for tracking. Native implementation was explicitly authorized on 2026-11-06; integration/deployment/rendering remain outside scope.

**Goal:** Keep each box's assigned source audio stable through Timeline edits, with reversible trimming, silent new boxes and coherent generation/playback.

**Architecture:** Store non-destructive windows by stable box ID on each opted-in audio lane. A pure timing module in each runtime resolves the same versioned representation, verified against shared fixtures; all conditioning, cue and assembly consumers use those windows. Preserve existing unlocked behavior and editing history rather than adding a separate audio editor.

**Tech Stack:** Existing Python, PyTorch audio tensors, native ES modules, Node test runner, unittest and the existing Playwright smoke pattern; no new runtime dependency.

**Spec:** [Approved design](../specs/2026-11-06-box-audio-range-lock-design.md). Read it before executing this plan.

## Global Constraints

- "Add **Lock audio to boxes** per audio lane, off by default for both new lanes and existing saved projects. No project-wide preference is added."
- "Never write sliced audio files or change playback speed to achieve the binding."
- "Do not automatically enable **In the full video**, mute whole boxes, or change the existing generated-versus-original soundtrack policy."
- "Existing normalization, joining and grid constraints still apply."
- "Do not rename or repurpose its saved `locked` field, or relax its restrictions as a side effect of this feature."
- "Re-enabling captures fresh overlaps from the continuous lane on the current Timeline; it does not silently revive an older binding snapshot."
- Readiness: Node 20 or later; use ComfyUI's Python for CPU package tests. No GPU/model run, deployment, restart, PR or release is part of this plan. Native execution is authorized.

## Review Focus

1. Fractional audio placement, nonzero source-in and a sample rate such as 11025 Hz must not duplicate/drop boundary samples (Tasks 1 and 3).
2. Split a shortened box, then extend both halves: its hidden tail must have exactly one owner (Task 2).
3. A selected soundtrack lane with an empty locked map must produce silence instead of falling back to generated audio (Task 4).
4. Native/attached project saves and asynchronous unlock confirmation must not overwrite a newer edit or lose bindings after a failure (Tasks 2 and 5).
5. An existing inserted bridge may block enabling when soundtrack playback would change; reference-only/non-conflicting lanes must remain eligible (Tasks 4 and 5).

## File and interface map

Create `h3_continuity/audio_windows.py` and `web/h3c_audio_windows.mjs` for pure binding validation, capture and resolution. Do not move unrelated audio code into them. Existing `audio_tracks.py` continues owning waveform slicing/mixing; `h3c_audio_lanes.mjs` continues owning controls/drawing/audition. All other files are narrow adapters listed in their task.

Use this concrete storage contract; it is an implementation choice permitted by the spec:

```json
{"box_windows":{"version":1,"source":{"file":{"type":"input","subfolder":"h3_audio","filename":"voice.wav"}},"placement":{"start":0,"source_start":30,"duration":8},"by_box":{"a":{"offset":0,"source_start":30,"duration":4},"b":{"offset":0,"source_start":34,"duration":4}}}}
```

`box_windows` lives on an existing `audio_clips` item. Its absence means unlocked; an empty `by_box` means locked and unassigned. `placement` preserves the continuous fields, which remain on the clip and must match while locked. `source` uses the existing effective-origin descriptor (`file` or `source`), not a new asset system; compare against effective reference routing to detect identity changes. Keep external same-file byte changes under existing fingerprint detection. Add the reader token `box-audio-windows-1` only while any lane contains this field. Snapshot descriptions/layer/soundtrack selection only through existing lane state, not inside every binding.

**Pure types:** `BoxSpan = {id: str, start: seconds, duration: seconds}` on the bridge-free played Timeline; `Window = {box: str|null, offset: seconds, start: seconds, source_start: seconds, duration: seconds}`; all intervals half-open. `offset` is box-local for bound windows and zero for continuous windows. `resolve(clip, boxes)` returns the original continuous window for unlocked lanes, or the currently audible intersections for bound lanes. A `box` value of null identifies the continuous case. `by_box` retains hidden tails; resolved windows never do. Retaining the local offset also lets assembly follow box identity when a saved outdated take has a different length from the current planned box.
