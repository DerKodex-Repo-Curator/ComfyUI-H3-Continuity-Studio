# H3 writer guidance

Automatic planning defaults to short, independently editable boxes, including for continuous takes. For example, a 15-second take can add 2 + 3 + 4 + 4 + 2 seconds across continuing boxes; this is illustrative, with no required count or minimum preferred length. The Timeline carries the previous latent and motion without a cut, pause or pose reset. Prefer generated clips under about ten seconds, replay included. Longer boxes remain allowed for an explicit user request or a concrete benefit continuation cannot preserve, explained in the beat. Continuity or a locked camera alone does not justify a long render. Fixed Timelines keep their existing boundaries.

Internal `[Shot N]` sections give distinct action stages or views their own timing, including within a continuous or static view. One simple stage needs only one section. The plan records `cut`; only `true` inserts a camera cut. The compiler preserves continuous views and does not insert cut-specific audio wording or transition markers at a continuous boundary. Older saved replies without this field retain their original later-section cuts. Feedback preserves the original cut/continuation choices.

Video plans now assign actions and exact dialogue to stages. Code allocates contiguous integer-frame windows inside each box's new time, after replay, using natural duration estimates and a speech budget. It rejects plans that need more time instead of accelerating them; only the Timeline's frame-grid rounding can reduce an action's estimate. Sequential lines use separate stages; planned simultaneous speakers share a stage. Code inserts the planned action verbatim. A continuing box starts from the actual final pose and motion in the supplied frames. Written endings are predictions, so code does not restage them as opening facts. The writer cannot replace that composition or camera boundary. Code also freezes the planned ending goal and renders it at the box's final timestamp, so reaching or grasping does not silently expand into the next box's lift or placement. Named prop identities refer to the same physical instances as they move, including at their destinations. These prompt constraints do not substitute for inspecting rendered frames. The writer returns sound, vocal delivery and any remaining visual fields, without timestamps or spoken text. Delivery cannot repeat the spoken words. The compiler inserts the original words and emits one interval for action and simultaneous speech.

Invalid, truncated or unstructured replies stay in the Story panel's expandable drafts and server recovery. They never replace a Timeline prompt or update a character's look. Dependent continuations wait for a valid ending; later independent cuts can finish. Saved sources retain their stage schedule and dialogue, which feedback and recompilation must preserve. Changing a box's length or replay requires rewriting its schedule before rendering. Existing saved shots remain readable, and legacy box rewrites retain their assigned dialogue. No automatic correction request is made.

At render time, a continuation also uses the preceding saved final image as a native image guide at the first new frame, immediately after replay. Frozen overlap latents alone constrain only the replay, so newly sampled frames can otherwise reset pose. An explicit guide at that frame takes precedence. Latent-only saved segments without a final image still use latent continuation. For exact prop counts and strict action endpoints, inspect and accept native opening and ending guides before rendering; text alone cannot establish that generated pixels satisfy those constraints. Keep adjacent stage targets mechanically compatible: turns, gaze changes and steps need playable time, rather than a new opening pose imposed immediately after the seam. A matching first frame alone does not establish smooth motion in the frames after it.

Stage writers choose audio through typed sound kinds, loudness and acoustic qualities; vocal delivery uses volume, pace and tone. Music and audio-reference roles are typed too. Code builds the audio sentences, so these fields cannot contain visual action prose. Empty effect arrays add no sound; an empty instrument list adds no music. Saved sources retain the typed choices, and recompilation rejects audio prose that no longer matches them. The current sound categories are defined in `h3_continuity/story_audio.py`.

Appearance is read-only for stage writers: `subject_updates` must be empty. New cast descriptions come from the initial plan; explicit Cast/Bible edits and scheduled looks remain authoritative. Make an intended appearance change there before writing its boxes. Pose, gaze, movement, position and prop ownership belong in stages and ending state, and cannot replace a character or prop description.

The Fast box writer combines its mode and field contracts with shared shot-writing guidance adapted from the [MiniMax H3 Singularity enhanced writing specification](https://huggingface.co/WarmBloodAban/Minimax-h3_Singularity/blob/af671d9214a6e41ab8c2f43e9f871ea56246115f/MiniMax_H3_Singularity_Prompt_Writing_Specification_Enhanced_EN.md), read on 2026-10-01. The source describes practical corpus-derived writing advice, not official implementation rules.

The shared guidance covers composition and starting pose, causal action progression, continuous background motion, camera framing, visible acting, triggered effects and physical responses, concrete lighting/materials, and state across cuts. Field-specific reference, summary, dialogue and audio rules stay in the writer's own instructions rather than being repeated in the shared guidance. Action complexity follows available time, so longer performances can contain detailed choreography and short clips remain playable. Camera speed, amplitude and focus changes are specified when meaningful; quiet holds and static framing remain valid. State follows continuous action across angle changes, while planned changes of time or place may establish a new state.

The current creative Guide takes priority. Mode, replay boundaries, duration budgets, exact dialogue, subject IDs and compiler-owned syntax retain their existing contracts. Reference appearance stays separate from frame anchoring and timed action. The source's full-reference template is not applied to other modes, and no new retention categories are introduced. Dialogue, synchronized effects, continuous ambience and audience-only music keep their existing fields. Descriptions are English; supplied dialogue, lyrics and visible text retain their original language.

Fast's Ref2VA schema now requests a concise semantic `summary` of the main action's progression and reached state across all shots. The compiler uses that summary instead of copying the opening composition, resolving IDs for subjects used anywhere in the clip without attaching absent references. Other modes do not request or emit this field.

The shared guidance is stored locally in `story_prompts.H3_WRITING_GUIDANCE`; there is no runtime download or additional LLM call. Fast receives compact instructions without the complete technical guides. The planning request does not receive this guidance. Saved prompts acquire this advice when rewritten. Automated checks cover the Fast writer in every H3 mode and a one-request multi-shot Ref2VA write, including later-shot subjects, verbatim dialogue and compiled action/outcome summary. These checks establish the instruction and compiler integration; rendered quality still requires reviewing generated clips.

Uploaded Idea images can also be optional Ref2VA guidance references. The official [MiniMax H3 full-reference guide](https://github.com/MiniMax-AI/MiniMax-H3/blob/b7227fa6a6206e9fb30562383d39e53cf3866a48/skills/h3-prompt-writing/references/ref-en.txt), optionally installed as `h3_continuity/h3_guide/ref-en.txt`, distinguishes reusable visual attributes from concrete frame anchors (sections 2.1, 2.2, 3 and 4.1). Planners select relevant images independently of visible cast. The Fast and bible writers specify each contribution in `image_guidance`; the compiler cites one or more source pictures inside a guidance `<Subject N>` definition, applies `reference generation` and `weak_reference`, and explicitly excludes reproducing the source images, their layouts, people, objects or text. It does not create standalone picture anchors or assign native first/last frames. Images only contribute their stated attributes, such as palette, texture, lighting, atmosphere or composition. Only images used by a compiled prompt are persisted as Studio pictures and passed to H3. N idea uploads remain available, while each clip retains H3's combined nine-image limit. Prompts and transport are tested; actual model adherence requires reviewing generated video.
